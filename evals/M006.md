## Scope and accounting boundaries

M006 adds JPMorgan Chase & Co. (JPM), FY2026 Q2, to the existing extraction,
deterministic reporting, shared Responses API, evaluation and investor
presentation architecture. Existing MSFT and CAT behavior is preserved.

The bounded eight-metric contract covers consolidated reported GAAP total net
revenue, net interest income, noninterest revenue, net income, diluted EPS,
provision for credit losses, loans and deposit liabilities. Quarterly flows
compare April-June 2026 with April-June 2025; stocks compare June 30, 2026 with
December 31, 2025, since year-end rather than YoY. Six-month/YTD observations,
managed revenue substitutions, net-income-applicable-to-common substitutions,
and net/retained/average-loan substitutions are excluded.

Three AI interpretation topics each occur exactly once with eligible structured
SEC citations and a required defining source:

| Topic | Accounting boundary | Defining source |
|---|---|---|
| Reported versus managed | GAAP headlines versus fully taxable-equivalent (FTE) management reporting; FTE does not change net income | `reported_to_managed` |
| Credit-loss measures | Quarterly provision expense, realized net charge-offs and disclosed net additions versus dated allowance stocks and their scopes | `credit_context` |
| Significant earnings items | Disclosed Visa-related net gain and other equity investment gains, separately from recurring operating performance; no invented adjusted earnings/EPS | `significant_items` |

### Step 4: shared API integration and live attempts

The JPM integration reuses the existing Responses API path with `gpt-5-mini`,
strict structured output and zero SDK retries. Python owns all financial facts,
changes and reconciliations; the model supplies only three interpretation
notes and permitted span IDs. Raw responses are saved before parsing and
independent evaluation. Failed evaluation blocks report generation.

The original offline integration checkpoint passed 836 tests and five explicit
MSFT/CAT regressions. A preliminary approval review rejected execution before
a request was sent. Later explicit user authorization permitted the reviewed
payload and destination. That earlier authorization block is resolved.

**Attempt #1:** the restricted-sandbox request failed with `APIConnectionError`;
no response ID or usage was returned. Its chained exception was not retained.
Subsequent credential-free diagnostics resolved DNS but TCP was blocked with
Windows error 10013. An approved outside-sandbox connectivity test established
TCP, verified TLS 1.3 and received HTTP 421, confirming HTTPS connectivity.
This supports sandbox restrictions as the likely cause of attempt #1; it does
not retrospectively prove the original request's delivery stage.

**Attempt #2:** separately authorized outside the sandbox, using the same
reviewed request bytes and a separate ledger, completed successfully with HTTP
200. There was exactly one request for this attempt and no automatic retry.

- Response ID: `resp_0663c57c543b54c9006ae624ca70c087d29fece02272d989eb`.
- Returned model: `gpt-5-mini-2025-08-07`.

### Step 4 offline diagnosis and scoped corrections

Offline tracing showed that $675 million is the total FTE adjustment, $58,022
million is managed revenue, and $564/$111 million are the noninterest/net-interest
component adjustments. The values were source-supported; nearest-measure
matching was defective. Rounded credit disclosures were not being subtracted
by the validator, and the 31,531 million firmwide allowance scope was correct.

The corrected `m006-narrative-v2` validator accepts exact defining-source labels
only when supported by the topic's selected structured spans; arbitrary labels,
URLs, unsupported markup and cross-topic citations still fail. Typed FTE roles
bind adjustments to their measures separately from reported/managed totals.
Bounded Unicode hyphens are recognized. False explicit arithmetic involving
rounded operands is rejected, and allowance scopes remain distinct. Future
instructions require citations through `span_ids`, without source-label prose.
The JPM formatting gate accepts safe intraword underscores without changing
MSFT/CAT formatting behavior.

With 55 new regression cases, the offline checkpoint passed 891 tests. The
immutable attempt #2 response then passed independent response, assembled-report
and presentation evaluation, with no remaining automated failures. Reports
were generated in a new offline-replay directory. The original failed
evaluation was not overwritten, nor was the response repaired or regenerated.

### Step 5: presentation-only polish
