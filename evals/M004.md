# M004-A: Investor Report Renderer

M004-A adds a deterministic, offline Markdown view over a saved, fully evaluated
quarterly report. It does not change M001, M002, M003 generation defaults, model
prompts, structured schemas, oracle fixtures, or evaluation rules. It makes no SEC
or model calls and adds no dependencies or infrastructure.

## Run

From the repository root, using the existing environment:

```powershell
.venv/Scripts/python.exe evals/render_investor_report.py --run evals/reports/m003/20261030T211637Z_de30375b
.venv/Scripts/python.exe evals/render_investor_report.py --run evals/reports/m002/20261029T182225Z_684dec81
```

`--output-root` optionally selects a separate output parent. The default is
`evals/reports/m004/`. Every execution creates a unique directory and never
replaces a prior report. Output paths inside the input run or containing the input
run are rejected. Exit code **2** means presentation automatic checks passed but
M004 human review is pending; **1** means the input gate or presentation failed.
This milestone does not process approvals or automatically return an approved
presentation status. It does not load `.env` or require an API key.

## Read-only M003 gate

The input must contain the original report, summary, source, sections, evidence,
archived oracle, saved evaluation, manifest, and a separate approved review file.
The source accession selects one of the two existing profiles. Saved profiles,
when present, must match configuration. Evidence is reconstructed from the saved
sections and pinned source identity. The saved summary must match the original
M003 renderer. For assembly-mode runs, raw notes and registry must reconstruct the
assembled report, and raw response text must agree with the parsed notes.

The unchanged independent M003 evaluator is called as a pure function against the
archived oracle and reviews. The saved automatic results and manual review records
must agree with the fresh result, and both automatic and overall pass must be
true. Missing, failed, pending, inconsistent, stale, or unknown-version artifacts
fail closed before output creation. Approved legacy M002 inputs are supported via
the known `m002-eval-v2` version; its evaluation differs from the profile-aware
version only in the version label. No validation requirements are omitted.

This avoids `run_report.reevaluate`, which writes to the source run. Every input
file is hashed and rechecked before new artifacts are written. The source artifact
set must also remain unchanged. The historical M003 evaluation and report files
are never rewritten. Exact quotation membership is checked in addition to the
existing evaluator's presentation-normalized membership check.

## Investor presentation

Initial renderer/evaluator: `m004-a-v1` / `m004-a-eval-v1`. The prose refinement
uses `m004-a-v2` / `m004-a-eval-v2`; earlier sample artifacts remain unchanged.

- The header states Microsoft, fiscal quarter, and both exact date ranges.
- The executive summary includes verified revenue and operating income YoY,
  plus the fastest-growing configured segment or exact ties. Growth leadership
  uses exact rational comparisons of validated current/prior values; rounded
  display rates cannot break a tie or establish one. If no segment grows, the
  report says so rather than calling a declining segment fastest-growing.
- Four GAAP headline metrics show USD billions to one decimal, and diluted EPS
  to two decimal places in USD/share. Billions use Decimal arithmetic with one
  final ROUND_HALF_UP operation. For example, 77,650 million displays as $77.7B,
  while 77,649 million displays as $77.6B. Existing validated YoY is formatted,
  not recalculated from the rounded billions.
- Two takeaways add an operating-income-versus-revenue comparison and the
  existing approved Cloud-growth/margin note. The latter is reused without narrative rewriting.
  Equal displayed growth rates do not produce an outperformance claim.
- The compact segment table follows the main summary, with every configured
  segment: three for FY2026 Q1 and two for FY2027 Q1.
- Human-readable reference links replace internal evidence hashes. Source URLs
  remain the pinned filing URLs; no unverified section anchors are invented.
- Supporting detail preserves every exact metric value string, unit, precision,
  GAAP basis, all three approved notes, and exact saved source quotations.
  Quote code fences accommodate embedded backticks without altering quote text.
  The JSON citation map retains evidence IDs, claim-bound span IDs, and quotes.

The renderer does not use the oracle as a source of presentation values: the oracle
is confined to the read-only gate. Approved narrative is displayed byte-exact.
If Markdown metacharacters or line breaks would require escaping or rewriting the approved note, rendering blocks
for formatting review rather than silently changing it. Source quotations remain
unchanged in structured artifacts and supporting Markdown.

## Separate M004 evaluation and review

Each output directory contains:

| Artifact | Purpose |
|---|---|
| `report.md` | Investor-facing draft |
| `supporting_detail.md` | Exact financial table, all notes, and source quotations |
| `presentation.json` | Exact/display metrics, narrative, comparisons, and source mappings |
| `supporting_detail.json` | Claim-to-evidence/span/quotation mapping |
| `input_manifest.json` | Renderer version, source run/profile, and all input file hashes |
| `m003_gate.json` | Read-only reproduction of the mandatory independent evaluation |
| `presentation_evaluation.json` | Separate M004 automatic results and pending overall status |
| `review_template.json` | Unresolved M004 review criteria bound to report/detail hashes |

Presentation checks cover exact values and basis, independent display rounding,
YoY formatting, comparative claims and ties, narrative preservation, source
identity, claim/span mapping, citation coverage, unexpected rendered text, report
sections, readable labels, and draft status. A conservative core-text budget of
220 whitespace-delimited tokens is an automatic screening check, not a claim
that the report has met the 30-second comprehension target. Notes are never
silently truncated to fit. Large notes block rendering for review.

All new presentations show **M004 review pending** even when the source M003 run
has approved qualitative reviews. `overall_pass` remains false. A human must still
assess approximately 30-second comprehension, emphasis, comparison clarity,
narrative context, citations, completeness, and actual Markdown rendering. The
review template is separate from the M003 reviews; M004-A does not implement an
approval/promotion command.

## Limits

Only the two existing Microsoft Q1 profiles are supported. Source hashes and
reconstruction detect inconsistent saved inputs, not coordinated tampering or
independent SEC authenticity. M003 did not originally sign reviews against every
artifact; fully coordinated edits to all saved records are outside this local
read-only gate's guarantees. The input manifest binds the presentation to the
bytes observed at rendering time. Word counts and automatic citation checks do
not establish semantic entailment, usability, investment suitability, or actual
reading time. All run artifacts remain ignored by Git. No commit or push is made
for M004-A until review.

## Focused natural-prose refinement

Renderer `m004-a-v2` replaces mechanical summary phrases with bounded financial
prose built only from validated exact values and saved YoY. The FY2026 summary is:

> Microsoft reported revenue of $77.7 billion, up 18.4% year over year, while operating income increased 24.3%. Intelligent Cloud was the fastest-growing segment, with revenue up 28.2%.

Segment names and leadership remain profile-derived, not hardcoded. Exact positive
ties use shared-leadership wording; flat or declining segment sets do not invent a
growth leader. Directional templates handle growth, declines, and changes that
round to zero. The executive summary describes the amounts and growth rates; the
first takeaway adds their relative comparison: operating income grew faster than
revenue (24.3% versus 18.4% for FY2026). It makes no claim about causes, operating
leverage, or margin expansion. Slower growth, declines, and equal displayed rates
have separate factual wording. The comparison is bound to operating income and
revenue citations rather than net income.

The second takeaway remains the complete approved Cloud-growth/margin note,
byte-exact in UTF-8 in both generated reports. All approved notes remain unchanged
in supporting detail. Neither a paragraph is shortened nor a new qualitative
interpretation introduced. Presentation evaluation `m004-a-eval-v2` independently
checks the revised wording, numerical relationships, and required citation IDs;
all prior gates and pending M004 review status remain in force.
